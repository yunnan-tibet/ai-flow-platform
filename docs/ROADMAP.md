# FlowInsight AI 路线图

更新：2026-10-11。产品范围以 [PRD.md](PRD.md) 为准，真实进度以 [LEARNING_STATE.md](LEARNING_STATE.md) 为准。

## 长期目标与执行原则

持续建设标准化、系统化、企业化的业务监控与分析平台。V1.0 是可交付基线，不是最终质量上限，也不等于商用就绪。保持既定里程碑，每次只推进一个可验收任务；后端及 AI 核心实现仍由用户手敲理解。

质量随功能形成，不以企业化为理由提前引入复杂架构。

## V1.0：既定 M0–M7 路线

工程要求随相关模块逐项设计和验收，下表不表示已经实现，也不要求在 M0 一次搭建全部工具。

| 阶段 | 既定交付目标 | 随阶段落实的工程要求 | 初始估算 |
|---|---|---|---:|
| M0 项目基线 | 仓库、环境、架构讨论、文档、技术验证 | 依赖锁定、忽略规则、统一开发入口、配置边界、最小测试与联调 | 8–16h |
| M1 Python 数据后端 | FastAPI/DB/迁移、HTTP/Mock 接入、Schema 映射、采样与接口 | 类型/接口与错误契约、按需分层、迁移、超时、输入校验、集成测试、仓库级检查 | 35–60h |
| M2 React Flow Studio | 画布、属性面板、变量、DSL、校验、发布、调试展示 | 前后端契约一致、DSL 版本与服务端校验、关键交互测试 | 55–95h |
| M3 Workflow Runner | DAG/分支、变量、Executor、Run 状态/存储、失败、幂等基础 | 状态转换约束、执行记录、失败测试、幂等与恢复边界 | 60–110h |
| M4 Trigger & Monitor | Manual、Cron、Webhook、Polling、规则、去重冷却与恢复 | 触发溯源、重复投递测试、调度所有权与重启语义设计 | 40–75h |
| M5 Agent / Tool / MCP | 通用 Agent、模型/工具、版本/授权、动态 MCP、Trace | 最小授权、即时撤权、调用限制、密钥保护、证据/输出校验、成本记录 | 75–135h |
| M6 指标监控与分析界面 | 历史、口径、告警、Dashboard、报告、跨业务验证 | 指标口径与证据追溯、查询边界、告警生命周期、异构案例回归 | 55–100h |
| M7 质量与交付 | 测试/Eval、Docker/CI、安全复核、Demo、文档与复盘 | 综合回归、CI 门禁、部署/运维说明、许可证检查、实际限制清单 | 35–65h |
| 合计 | 完整 V1.0，不包含全部企业化目标 | 随实际学习和实施情况修正 | 363–656h |

## V1.1 / 后续：可靠性强化与企业化

下列是长期能力方向，不是已批准的详细功能方案。开始前明确使用场景、设计取舍、独立工时与验收标准；已有基础不重复建设。

| 能力方向 | 需要取得的验收证据 |
|---|---|
| 身份与权限 | 角色与资源范围明确；未授权及撤权场景的拒绝测试 |
| 工作空间/租户隔离（有多用户需求时） | 数据、运行、工具凭证等资源的跨边界访问负向测试 |
| 审计与安全 | 关键操作可追溯、日志脱敏、密钥管理、依赖风险检查；按实际场景评估合规 |
| 执行可靠性 | 重试/幂等/任务所有权明确；重启、故障与恢复演练无不受控重复副作用 |
| 运维与交付 | 可观测告警、备份恢复演练、发布回滚演练与操作手册 |
| 容量与成本治理 | 代表性负载测试、资源/模型调用预算和限额；基于证据确定服务目标 |
| 扩展与兼容 | Connector/节点/工具扩展契约、配置/数据版本迁移、兼容性回归 |

商业化另行评估安全、合规、许可证、服务责任与运维能力。企业化不自动绑定微服务、Kubernetes 或插件市场；架构由需求和验证结果决定。
